## 0. 给执行 agent 的启动规则

1. 先读 `AGENTS.md`、本文件、`docs/当前进度.md`。`AGENTS.md` 的约束继续有效，尤其是不读取手机版、不修改 Unity 原项目。
2. 严格按第 8 节的工作包顺序推进。一个工作包一个分支（`ssc/wpNN-名称`），通过验收再合并到 `main`。
3. “完成”只有一个定义：工作包的验收项全部有证据，证据写入 `docs/parity/WPNN.md`（截图路径、数值、运行命令）。编译通过不算完成。
4. 所有 Unity 数值从场景、Prefab、ScriptableObject 或脚本读取，并写明来源文件。禁止凭观感手填。
5. 模拟器验证不了的项，标记为 `需真机`，继续做下一项，不要卡住，也不要写成已通过。
6. 遇到框架做不到的效果：先做不超过半天的技术验证，再记录差异、证据和候选方案。不得悄悄降级。
7. 不写参赛文书。Apple 要求文书由本人撰写，agent 只整理事实素材。
8. 用户 UI 规则：不用“·”做分隔；不放解释性废话；文案平实克制，面向焦虑、低落、压力大的用户；嵌套圆角同心；线宽 0.5；反馈是引导，不是评分；触觉和音效要稀疏。Moodi 语音字幕必须与录音一致，不得改写。

## 3. 产品结构：完整版加三分钟评委路径

同一套代码，两个构建配置，不砍功能。

- `Debug` / `Full`：完整 Unity 闭环，中英文，支持感官袋，时长不限。
- `SSC`（Swift 编译条件 `SSC_SUBMISSION`）：英文，默认无袋，首次启动走评委路径，资源只打包英文。

评委路径（总长不超过 2:50，每段都可跳过，没有倒计时 UI）：

| 时间 | 段落 | 内容 | 输入 |
|---|---|---|---|
| 0:00 | 开场 | 捏开糖果，Moodi 蹦出，空中写 MOODIUM，压缩到 15 秒内 | 看向并捏合 |
| 0:15 | 心情 | 心情色轮，推荐世界 | 拖动或点按 |
| 0:30 | 进入 | 虚拟感官袋自动放到面前桌面高度 | 滑动进入 |
| 0:40 | 救援 | Moodi 落入，按压 8 到 10 次救出 | 手触或看向捏合 |
| 1:20 | 房间生长 | 糖果屋或大树、花草雨生长 | 观看，可触碰 |
| 1:45 | 时空之门 | 水滴展开成门，走入或捏合进入点云世界 | 走动或捏合 |
| 2:20 | 心愿 | 选一句心愿，挂上风铃 | 点按 |
| 2:40 | 结束 | 回到现实，心情回看，收束画面 | 点按 |

规则：

- 评委路径用 `ProgressPace` 和专用参数缩短，不改完整版节奏。
- 任一段 20 秒无操作时，只给一次温和提示，再提供“Continue”。不能卡死，也不能催促。
- 感官袋作为可选增强保留，在结束页或设置中说明。提交版不得出现无法继续的“请看向贴纸”状态。

## 4. 现状审计

### 4.1 规模

- Swift App 代码 1,905 行；Unity Moodium 业务代码 231 个文件、42,085 行。当前约为 4.5%。
- 五组逻辑检查已在本机重新运行并通过。它们只覆盖旅程、计分、追踪、心情和校准规则。
- Swift 中完全没有以下模块：节奏和呼吸引导、音频 DSP、灵敏度、Shower、藤蔓、脚步生长、奖励序列、糖果屋、空间网格改造、传送门、点云、心愿风铃、日记、教程卡、粒子系统。

### 4.2 卡住的根因

1. **缺少视觉闭环**：agent 只能截到开场，看不到世界内部，所以无法迭代“一比一”。先做 WP2。
2. **逐脚本翻译**：Unity 的 PolySpatial、Shader Graph、协程要映射到 RealityKit 的 ECS、ShaderGraphMaterial、LowLevelMesh，不能按行翻译。
3. **状态集中**：`NativeScene` 和 `MoodiumSpace` 已同时承担流程、UI、加载和输入，继续堆功能会失控。
4. **资源未做预算**：直接转换的资源已接近 ZIP 上限。

## 5. 目标架构

```text
Moodium/
  App/            MoodiumApp, AppModel, BuildProfile(Full/SSC)
  Flow/           ExperienceRouter, JudgePath, WorldJourney
  Input/          ARSessionManager, InputRouter, HandInput, IndirectInput, SqueezeInput
  Spec/           UnitySpec.generated.swift（工具生成，禁止手改）
  Systems/        RealityKit System：Squeeze, Growth, Particle, Follow, Fade
  Features/
    Opening/ Mood/ Selection/ Calibration/ Rescue/ RoomGrowth/
    Explore/ Portal/ PointWorld/ Wish/ Journal/ Settings/ Guide/
  Rendering/      SoftBody, SplatMesh, ShaderGraph 包装
  Audio/          AudioDirector（AVAudioEngine，低通、节拍时钟、空间音）
  DesignSystem/   玻璃面板、按钮、字体、动效常量
  Packages/RealityKitContent/  Reality Composer Pro 材质
```

原则：

- `ExperienceRouter` 是唯一的流程状态源，每个 Feature 提供 `enter()`、`exit()`，退出时必须释放资源。
- 持续行为写成 RealityKit `System` 和 `Component`，不再在 View 里堆 `SceneEvents.Update` 订阅。
- 输入统一成 `PressEvent(source, worldPoint, closure, time)`。真手和模拟器间接输入走同一条链路。
- 部署目标保持 visionOS 2.x，高版本 API 用 `#available`。最终必须在 Xcode 27 的 visionOS 27 运行时验证。
